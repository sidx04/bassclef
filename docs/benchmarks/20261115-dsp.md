# Spectrogram: real FFT and buffer reuse

| | |
| --- | --- |
| Date | 15th November, 2026 |
| Files | `internal/dsp/fft.go`, `internal/dsp/spectrogram.go` |
| Benchmarks | `BenchmarkForward`, `BenchmarkSpectrogram` (`internal/dsp/bench_test.go`), `BenchmarkFromBuffer` (`internal/fingerprint/bench_test.go`) |

This report covers two changes, measured one after the other:

1. **Real FFT.** Replace the complex-to-complex FFT with a real-to-complex FFT that returns only the non-redundant half of the spectrum.
2. **Buffer reuse.** Stop allocating 3 slices per frame in `Spectrogram`.

| --- | --- | --- | --- | --- |

| `Forward`, memory/op | 128 KiB | 40 KiB | 0 B | no allocations |
| `Forward`, allocs/op | 2 | 1 | 0 | |
| `Spectrogram`, time/op | 465.8 ms | 208.7 ms | 197.0 ms | 2.4x faster |

| `Spectrogram`, allocs/op | 20,665 | 15,499 | 4 | |
| `FromBuffer`, time/op | 1,024.6 ms | 493.3 ms | 477.6 ms | 2.1x faster |
| `FromBuffer`, memory/op | 1,850.4 MB | 902.4 MB | 511.1 MB | 3.6x less |

All times are the mean of 10 runs. The full fingerprinting pipeline is about 2x faster, uses about a quarter of the memory, and stores about half as many fingerprints per song.

Step 1 gives almost all of the speedup. Step 2 is mostly a memory win: it saves only about 6% of `Spectrogram`'s time, because the FFT itself (about 32 µs × 5,166 frames, roughly 166 ms) now dominates.

**Step 1 invalidates existing catalogs.** Every hash changes, so all songs must be re-ingested (see the invariants in `CLAUDE.md`). Step 2 does not change any output: the spectrogram is bit-identical to step 1's, so it needs no extra re-ingest.

## Step 1: complex to real FFT

The old `CmplxFFT` copied each real-valued frame into a `[]complex128` with zero imaginary parts, then ran gonum's complex-to-complex FFT. It returned all 4,096 bins:

```go
func (c *CmplxFFT) Forward(input []float64) []complex128 {
	complexInput := make([]complex128, len(input))
	for i, v := range input {
		complexInput[i] = complex(v, 0)
	}

	return c.fft.Coefficients(nil, complexInput)
}
```

For real input, the spectrum is conjugate-symmetric: bin `N-k` is the complex conjugate of bin `k`, so `|X[N-k]| = |X[k]|`. Bins above `N/2` (the Nyquist frequency) repeat the lower half and carry no new information.

The new `RealFFT` uses gonum's real-to-complex FFT (`fourier.NewFFT`). It takes the `[]float64` frame directly and returns only the `N/2+1` = 2,049 non-redundant bins, from 0 Hz to Nyquist:

```go
func (r *RealFFT) Forward(input []float64) []complex128 {
	return r.fft.Coefficients(nil, input)
}
```

This saves work in three places:

- **No conversion.** The `complexInput` allocation and copy loop are gone.
- **Less FFT work.** A real-input FFT does about half the arithmetic of a complex FFT of the same length.
- **Smaller output.** 2,049 bins instead of 4,096, so `Magnitude` and everything after it handles half the data.

### Mirrored peaks downstream

`FindPeaks` scans every bin of every frame. With the full 4,096-bin spectrum, every real peak at bin `k` also showed up as a mirror peak at bin `4096-k`. On the benchmark signal, 203,939 of the 408,296 peaks (50%) were above Nyquist. `BinToHz` maps those bins to frequencies above 22,050 Hz, which the audio does not contain.

These mirror peaks doubled the landmarks and the fingerprint rows written to SQLite without adding any matching power: every mirror hash is fully determined by its real counterpart. With the real FFT, no peak lands above Nyquist, and peaks and landmarks both drop by half.

### Allocations per frame

After step 1, `Spectrogram` still allocated 3 slices per frame. Their sizes come from the Go allocator's size classes:

| Slice | Requested | Allocated |
| --- | --- | --- |
| `windowed` | 4,096 × 8 B = 32,768 B | 32,768 B |
| FFT output | 2,049 × 16 B = 32,784 B | 40,960 B |
| `Magnitude` result | 2,049 × 8 B = 16,392 B | 18,432 B |

That is 92,160 B per frame. For 5,166 frames, that's 476.1 MB, which matches the benchmark. Before step 1, each frame also allocated the 64 KiB `complexInput`, and the FFT output and magnitudes were twice the size.

## Step 2: buffer reuse

Only the magnitude rows need to outlive the loop. The `windowed` copy and the FFT output are scratch space: each frame overwrites them completely. Step 2 allocates them once and reuses them, and puts all magnitude rows in one backing array.

```go
windowed := make([]float64, len(window))
var coeffs []complex128
var backing []float64

for i, frame := range frames {
	// length check against window, then:
	copy(windowed, frame)
	applyWindow(windowed, window)

	coeffs = fft.Forward(coeffs, windowed)

	bins := len(coeffs)
	if backing == nil {
		backing = make([]float64, len(frames)*bins)
	}

	row := backing[i*bins : (i+1)*bins : (i+1)*bins]
	spectrogram[i] = Magnitude(row, coeffs)
}
```

To make this possible, `Forward` and `Magnitude` now follow gonum's `dst` convention: if `dst` is nil they allocate, otherwise they write into `dst` and return it.

```go
Forward(dst []complex128, input []float64) []complex128
func Magnitude(dst []float64, spectrum []complex128) []float64
```

Design points:

- **Bin count comes from the FFT.** `Spectrogram` does not assume `len(window)/2+1`. The first `Forward(nil, …)` call allocates the output, and its length sizes the backing array. Any `FFT` implementation works, including the test stub, which returns one bin per sample.
- **Rows are capped.** The 3-index slice caps each row's capacity at its length, the same pattern as `SplitFrames`. An `append` on one row allocates a new array instead of overwriting the next row.
- **Frame length is checked explicitly.** Before, a frame with the wrong length failed inside `applyWindow`. Now `windowed` always has the window's length, so `copy` would silently truncate a longer frame or leave stale samples from a shorter one. `Spectrogram` now checks every frame against the window and returns an error naming the frame.

### The 4 remaining allocations

| Allocation | Size |
| --- | --- |
| `spectrogram` (row headers) | 5,166 × 24 B, rounded to 131,072 B |
| `windowed` | 32,768 B |
| `coeffs` (first `Forward` call) | 40,960 B |
| `backing` (all magnitude rows) | 5,166 × 2,049 × 8 B = 84,681,072 B |

The total is about 84.9 MB, which matches the benchmark. Almost all of it is `backing`, which is the spectrogram itself and has to exist.

`BenchmarkForward` now reuses one `dst` buffer, so it reports 0 allocations and measures the transform alone.

## Other changes

- `fft_test.go`: both tests check that `Forward` returns `size/2+1` bins, and the sine-wave test no longer expects the mirror bin 7 (step 1). A new test checks that `Forward` writes into a non-nil `dst` (step 2).
- `spectrogram_test.go`: the stub FFT follows the `dst` contract. New tests check that rows are capped, that a wrong-length later frame is rejected, that empty input works, and that `Magnitude` writes into `dst` (step 2).
- `cmd/bassclef/cli.go`: the `spectrogram` command printed `cfg.FFTWindowSize` (4,096) as "Bins per frame". It now prints `cfg.FFTWindowSize/2+1` (2,049) (step 1).
- `types.go`: the `FFTWindowSize` comment refers to `RealFFT` instead of `CmplxFFT` (step 1).

## Setup

- Input: synthetic 240 seconds signal at 44,100 Hz: 10,584,000 samples, 85 MB as `float64`
- Config: `DefaultConfig()` -> FFT size 4096, hop 2048, which gives 5,166 frames
- Peak and landmark counts: `DefaultPeakConfig()` and `DefaultLandmarkConfig()`, after `NormalizeGain`, the same steps as `FromBuffer`
- Go 1.27.1, darwin/arm64, Apple M5
- 10 runs per version (`-count=10`)

The baseline numbers include the uncommitted `Magnitude` change from `cmplx.Abs` to `math.Sqrt(re*re + im*im)` in `spectrogram.go`, so step 1 isolates the FFT change only. Step 2's baseline is step 1's result; no other code changed between the two runs.

Step 2 was checked for identical output: on a 30 seconds slice of the benchmark signal (644 frames), every bin of the new `Spectrogram` equals the per-frame-allocating version exactly (`==`, not within a tolerance). Peak and landmark counts on the full signal are also unchanged.

Reproduce:

```sh
go test -run '^$' -bench . -count=10 ./internal/dsp/ ./internal/fingerprint/ > new.txt
```

## Next target

`Spectrogram` now allocates only what it returns. Most of `FromBuffer`'s remaining 511 MB/op and 87 allocs/op come after the spectrogram, in `FindPeaks` and `GenerateLandmarks`: about 426 MB/op is left once `Spectrogram`'s 84.9 MB and `SplitFrames`' 128 KiB are subtracted. Profile them before changing anything:

```sh
go test -run '^$' -bench '^BenchmarkFromBuffer$' -memprofile mem.out ./internal/fingerprint/
go tool pprof -top -sample_index=alloc_space mem.out
```

For time, the FFT is now about 85% of `Spectrogram`. The remaining option there is to spread frames across goroutines, each with its own `RealFFT` and buffers.

**Follow-up:** the profile showed `GenerateLandmarks` as the largest allocator. It was fixed next; see [20261115-fingerprint.md](20261115-fingerprint.md). `FromBuffer` dropped from 511.1 MB/op to 178.8 MB/op.
